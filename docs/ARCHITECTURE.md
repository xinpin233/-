# 模块边界与后续扩展

## 数据流

`main.tscn` 的根节点是组装入口。`game_controller.gd` 创建状态、播放控制器和音频系统，并连接界面信号。音频条只发出 `preview_requested` 与 `move_requested`，不读取关卡答案，不直接操作音频播放器。

`SoundRunState` 持有当前排序、尝试次数和五种运行状态：编辑、播放、暂停、成功、失败。`OrderRules` 是不依赖场景树的纯规则模块，负责顺序移动及与正确顺序比较。新规则可以先从这里扩展。

`SoundPlaybackController` 是唯一的剧情时间轴，按关卡的声音时隙启动音效，并通过 `frame_changed` 推进画面、字幕、音频高亮与总进度。排序在开始播放时复制，运行中不允许改动。错误分支到达 `failure_time` 即停止；正确分支播放到 `duration`。

`SoundAudioDirector` 分别管理环境声、剧情音效和试听三个播放器。停止、失败、重播会清理旧声音和暂停状态。暂停冻结剧情时间、环境声、音效及真实视频。静音仅作用于本游戏播放器。

`SoundFilmViewport` 管理胶卷滑动，使用四个原生绘制的 `SoundComicFrame`。`SoundStoryPresenter` 单独存放示例故事字幕。这两个模块都属于可替换的表现层。

## 修改关卡

在 Godot 中选中 `resources/levels/behind_the_door.tres`：

| 配置 | 含义 |
| --- | --- |
| `clips` | 本关所有音频资源 |
| `initial_order` | 初始音频 ID 顺序，每条必须恰好一次 |
| `correct_order` | 通关音频 ID 顺序，每条必须恰好一次 |
| `slot_duration` | 每个可排序声音的固定时间窗口 |
| `stage_starts` | 当前演示的四个分镜起始时间 |
| `duration` | 完整放映时长 |
| `failure_time` | 错误分支提前停止的时间 |
| `ambience` | 与可排序声音分离的环境底声 |
| `success_video` / `failure_video` | 正式视频的 `res://` 资源路径，留空使用演示分镜 |
| `success_*` / `failure_*` | 结局标题和说明 |

本原型使用固定时隙；音频应剪辑到时隙长度以内，切换时隙会截断上一段。增加更多音频时，排序及音效调度支持任意数量，但界面高度需要配合增加或加入滚动容器。「门后」画面与字幕依赖两条指定声音及四段剧情；新增故事需单独实现对应表现层。

目前一次播放使用一条预选分支，规则为完整顺序匹配。多个有效解法、逐节点分支、音频长度不等、存档、关卡选择、正式死亡演出不在本轮原型范围。

## 接入正式视频

把 Ogg Theora `.ogv` 放到 `assets/video/` 并配置资源路径。成功和失败视频共用时间零点，与音频时隙和分镜节点对齐；视频内音轨静音，环境声和音频条仍由音频系统播放。该接入口用于预先剪好的完整分支。

Godot 的实际视频解码与游戏时钟分别推进，当前没有做长视频漂移校正、任意拖动定位、异步加载或片段拼接。正式长片接入时应增加以媒体时钟为准的同步方案。当前九秒原型通过统一开始、暂停、停止管理保持流程一致。
