# 四段 Demo 的制作流程

本版使用四个三秒时隙，共十二秒。声音片段、画面和指针使用同一时间轴。四个色块可试听与拖动。原序为滴答、惊叫、敲门、警铃，成功序为惊叫、滴答、敲门、警铃。

## 占位演出

滴答时靠近门，惊叫时后退，敲门时选择前进或回撤，警铃时落闸收尾。成功路线回到左侧安全出口，失败路线走向右侧卷闸。当前是固定答案的教学原型，其他排列按失败路线演出。人物走位用于验证制作流程，正式表情和叙事动作由动画素材接入。

## 音乐交付

在 Godot 中打开 resources/clips/ 下对应的 tres，将 Stream 属性拖入正式 WAV 或 OGG。四段各三秒，短声音可留尾部静音。Tint 控制色块颜色。保持 Id，拖动排序与剧情仍按 Id 关联。环境声在 resources/levels/behind_the_door.tres 的 Ambience 中替换。

## 美术交付

每段可制作两个独立 tscn，分别用于正常解读和警觉解读。在对应音频资源的 Calm Scene 和 Alarmed Scene 中拖入场景。

场景使用 1100 × 825（4∶3）的画布，左上角为原点，根节点用 Node2D 或 Control。美术原图可使用 1600 × 1200，再等比例放进此画布。场景根节点下添加名为 AnimationPlayer 的节点，动画命名为 play，长度三秒。时间轴会主动定位动画时间，暂停和重播会同步。无需 autoplay。动画应使用属性轨道驱动图片位置、透明度、帧序号等，避免依赖方法轨道执行游戏逻辑。

未绑定动画场景时自动使用原生占位画面。绑定后整个分镜由素材场景呈现，需把背景和边框一起放入场景。

## 程序和策划

behind_the_door.tres 配置片段集合、初始顺序、正确顺序、每格时长与四个切镜时间。当前教学原型保留四格约定。更换整体节奏时同步修改 Slot Duration、Duration、Failure Time、Stage Starts 与动画长度。

先验证默认失败与正确顺序成功，再检查任意排列、试听、拖动、暂停、重播。正式资源逐段替换后用同一流程验收。
